# Subok World Deferred Scope

Conclusion: deferred scope is not rejected scope. It is delayed so Subok World V0 can prove the territory-and-faction loop first.

## Current V0 Ban List

The following features must not be implemented in V0:

- individual user trading
- real-time market simulation
- detailed item shop
- complex price table
- direct main-game runtime integration
- account inventory or ownership ledger
- server-persistent economy
- cash-like economy
- coin, token, NFT, or external asset design

## Why These Are Banned For V0

Subok World V0 needs to answer a strategic question before it answers an economic interface question.

The strategic question is:

> Can faction and territory changes create meaningful next-battle conditions?

If V0 starts with user trading, item prices, persistent ownership, or a live market, the project will create operational and balance problems before proving that the world layer improves the war game.

## Deferred Ideas

These ideas can be revisited only after P0 battle stabilization and an isolated Subok World V0 simulation:

- faction-to-faction arms trading
- neutral merchant faction
- war-news expansion
- item and vehicle price pressure
- tank-part scarcity
- territory-based supply contracts
- JSON handoff from Subok World to the battle game
- battle-result JSON handoff back to Subok World
- season-scale territory war
- admin-only world-state viewer

## Future Reconsideration Gate

A deferred feature can return only when all of the following are true:

- the main P0 battle lane has a clear gate decision
- Subok World V0 has an isolated simulation plan
- the feature supports territory, faction, production, or next-battle conditions
- the feature does not require account economy, live user trading, or external money
- the feature can be tested without confusing battle-runtime bugs

## Safe Future Order

If Subok World continues after V0, the safer order is:

1. territory and faction data
2. isolated turn simulation
3. war-news summaries
4. next-battle condition JSON
5. one-way read-only battle setup experiment
6. battle result export
7. two-way world loop
8. limited market pressure
9. user-facing economy ideas

Do not skip directly to user-facing economy features.
