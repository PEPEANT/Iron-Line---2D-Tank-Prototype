# 보급/장비 시스템 설계도 (병과 제거 → 보급 인출)

작성: 2026-07-05. 상태: **설계도만. 구현은 R2 우선순위 3번 (래칫 G0 + 사망UI + 침대전투 계측 이후).**
방향: 게임 전 병과 선택을 없애고("1분 시작" 원칙), 전장 보급품에서 무기·장비를 꺼내 쓰는 시스템으로. 계급은 유지.

각 절에 분업 태그를 단다: `[Codex]` = 이 문서 스펙대로 단순 구현 위임 가능. `[난제]` = 애매함/판단이 남아 있어 Fable(또는 사람) 세션에서 설계 확정 후 진행.

## 1. 병과는 뚝 끊지 않는다 — 3단계 이행

| 단계 | 내용 | classId의 운명 | 태그 |
| --- | --- | --- | --- |
| S1 | 게임세팅에서 병과 선택 UI만 숨김. **전원 기본 소총 + 보병 에셋 단일로 즉시 시작** (2026-07-05 확정) | 내부 데이터로 온존 — AI 편성/온라인 슬롯 코드 무수정 | [Codex] |
| S2 | 보급상자 도입, 장비 획득이 상자 기반으로 전환 | "시작 프리셋" 의미로 축소 (공병 프리셋=RPG 들고 시작 같은 내부값) | 상자=[Codex], AI 사용=[난제] |
| S3 | classId 참조 전면 제거 + 온라인 슬롯 ID 개편 (blue-infantry → blue-1 등 team+seat) | 삭제. 계급 시스템과 완전 분리 | [난제 — 서버/클라 동시 마이그레이션] |

S1만으로 "1분 시작"이 즉시 개선된다. S3는 온라인 R2 재설계와 같은 세션에 묶는 것이 안전.

## 2. 보급 사물함 구현 [Codex — 스펙 고정됨]

보급 사물함은 **맵 사물이다** — 게임 시작 시 맵에 배치돼 있고, 열면(E) 슬롯 그리드가 나와 드론·치료킷·RPG 등을 가져간다. 맵에디터 V2 도감(`object-catalog.js`)에 `supply-locker` 항목으로 등록 (category: 구조물). 에디터 P1 전에 구현할 경우 임시로 scenery 배치 경로를 쓰되 필드는 아래와 동일하게.

```js
"supply-crate": {
  name: "보급상자",
  footprint: { w: 36, h: 24 }, collision: true, cover: "light",
  spriteSlot: "object.supply-crate",   // 에셋팩 규약 — 그림 없으면 벡터 상자
  stock: { rifle: 99, smg: 99, rpg: 2, grenade: 6, medkit: 4, mortar: 1, atgun: 1, sandbag: 8 },
  team: "neutral" | "blue" | "red",    // 적 상자는 노획 가능 (기본: 팀 상자)
  interactionRadius: 46
}
```

- 배치 기본값: 각 팀 스폰 1개 + 거점 근처 1개. 맵에디터로 추가 배치 가능.
- 재고는 방/매치 상태에 포함 (온라인 동기화 대상). 소진 시 빈 상자 표시.
- 보급 투하(수송 이벤트로 재보급)는 후속 확장 — 필드만 예약: `resupplyEventId`.
- 기존 코드 재사용: 무기 교체는 `InfantryUnit.setWeapon()`(이미 존재), 소모품은 `equipmentAmmo`(이미 존재)에 가산. **새 인벤토리 시스템을 만들지 않는다.**

## 3. 줍는 모션 [Codex — 에셋 불필요, 코드 포즈로]

탑뷰 2D에서 스켈레탈 애니메이션은 필요 없다. 다음 4요소로 "줍는 행위"가 읽힌다:

1. 상자 `interactionRadius` 안에서 `E키` **홀드 0.9초** (점령 게이지와 같은 진행 링을 유닛 위에 표시 — 기존 캡처 게이지 렌더 재사용).
2. 홀드 중 유닛 포즈: 무기 각도 내림 + 반지름 미세 축소 (엎드림 전환이 쓰는 코드 포즈 방식 재사용). 이동/피격 시 즉시 취소.
3. 완료 순간: 무기/아이템 스프라이트 교체 + 상자 위 획득 텍스트 1줄 (킬로그 스타일, 1.2초 페이드).
4. 사운드·이펙트는 에셋팩 슬롯 예약만: `ui.pickup.sound`, `ui.pickup.flash`.

모바일: 상자 근처에서 상호작용 버튼 노출(기존 탑승 버튼 패턴 재사용), 홀드 동일.

## 4. UI — 슬롯바 6키 (2026-07-05 확정, 5키 스펙 폐기)

```text
[1 주무기] [2 보조무기] [3 중화기] [4 지원장비] [5 투척류] [6 설치류]
```

- 1 주무기: 기본 소총, 교체형 주화기.
- 2 보조무기: 권총, 예비 단화기.
- 3 중화기: RPG, 대전차, 기관총.
- 4 지원장비: 드론, 치료킷, 탄약팩.
- 5 투척류: 수류탄, 연막탄.
- 6 설치류: 지뢰, 포탑, 설치형 장비.
- **A단계: 시작 시 채워진 것은 1번(기본 소총)뿐이다.** 2~6은 빈 슬롯으로 시작 — 보급 사물함을 열어야 채워진다. "빈 슬롯이 보인다 = 사물함에 가고 싶어진다"가 의도된 동선.
- **B단계: 사물함 인출 아이템이 정해진 슬롯으로 들어간다.** RPG는 3번, 드론·치료킷·탄약팩은 4번, 투척류는 5번, 설치형은 6번.
- 아이콘: `assets/weapons/<id>.png` 규약 그대로 — 신규 id(mortar, atgun, sandbag, medkit) 4장 추가, 플레이스홀더 생성기 재사용.
- 상자 앞 E 홀드 완료 시: **단순 그리드 팝업** (상자 재고를 슬롯 그리드로, 남은 수량 뱃지, 클릭/키로 교체). 설명 텍스트 없음 — 텍스트 다이어트 준수. 팝업 열린 동안 게임 일시정지 없음(전장 위험 유지).
- 시체/버려진 무기 줍기는 같은 E 상호작용의 확장 — 후속.

## 5. AI 사용 규칙 [난제 — Fable 설계 필요]

아이템당 행동 로직 1개 원칙. 각각 판단 조건이 애매해서 설계 세션 필요:

- 재보급 판단: RPG/수류탄 소진 + 비교전 + 상자까지 위험 경로 아님 → 재보급 이동. (교전 중 상자로 달려가 죽는 바보 방지 조건이 난제)
- 설치형 판단: 박격포·대전차포 설치 위치 선정(사계/엄폐), 모래주머니 축성 타이밍(제압 상태에서 "누워만 있기" 대체 행동 — 침대전투 계획과 합류점)
- 분대 배분: 상자 재고가 부족할 때 누가 RPG를 가져가는가 (분대 내 역할 협상)

이 절이 이 시스템의 진짜 비용이다. 상자·UI·모션이 다 돼도 AI가 안 쓰면 "플레이어 전용 기능"으로 끝난다.

## 6. 검증 게이트 (구현 세션마다)

- S1: 메인→첫 교전 스톱워치 60초 이내 단축 확인 + `npm run check` + 템포 프로브 페이스 유지(6~12/min).
- S2: 상자에서 RPG 인출→전차 공격 성립 (수동 15분) + AI 재보급 행동 계측 카운터 (`supply:refill`, `supply:deploy-mortar` 등 — 침대전투 계측과 같은 방식).
- S3: 온라인 2인 방에서 슬롯 개편 후 입장→전투→결과 무결 + check:online 통과.

## 7. 하지 말 것

- 새 인벤토리/무게 시스템 발명 금지 — setWeapon + equipmentAmmo로 충분.
- 병과 데이터 일괄 삭제 금지 (S1~S3 순서 엄수).
- 아이템 6종 동시 투입 금지 — 6키 슬롯 구조 먼저, 아이템은 하나씩 (박격포부터).
- 상자 팝업에 설명문 넣지 않기.
