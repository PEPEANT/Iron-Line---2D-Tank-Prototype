# 모바일 시야 확보 설계도 — 구현 지시서

작성: 2026-07-04, Fable 5. 문제: 모바일에서 시야가 좁아 이동·조준이 어렵다.

## 원인 진단 (코드 확인됨, src/main.js 4201~4217)
- 카메라 줌 = `baseTargetZoom × cameraZoomPreference`, clamp [0.6, 1.45].
- **조준 시 줌아웃은 이미 구현돼 있다**: 전차 조준 0.76, 저격 0.72, RPG/드론 0.82, MG 0.88, 권총 0.94. 여기는 건드릴 필요 없음.
- 진짜 원인: `cameraZoomPreference`는 PC 휠로만 조절된다. **모바일은 이 값을 바꿀 수단이 없어 기본 1(좁은 시야)에 고정.** 클램프상 0.6까지 넓힐 여지가 있는데 못 쓰는 상태.

## 구현 지시 (3개, 순서대로)

### 1. 모바일 기본 시야를 넓게 (1줄급, 최우선)
- `src/main.js`에서 `cameraZoomPreference` 초기화 지점을 찾는다 (검색어: `cameraZoomPreference`).
- 모바일 조작 활성 시 기본값 **0.78** (PC는 1 유지). 모바일 판별은 기존 모바일 컨트롤 플래그 재사용 (검색어: `mobileControls` / `data-mobile-controls`).
- 효과: 화면 면적 기준 ~64% 더 넓게 보임. 이것만으로 체감 대부분 해결 예상.

### 2. 핀치로 preference 조절
- `src/systems/mobile-camera-gestures.js`에 핀치 스케일 → `game.cameraZoomPreference` 반영 (휠과 같은 대상 변수). 클램프 [0.6, 1.2] (모바일은 과확대 방지 위해 상한을 PC 1.45보다 낮게).
- 이미 핀치 처리 코드가 있으면 대상 변수만 cameraZoomPreference로 교체.

### 3. 설정에 시야 3단 토글 (선택, R1.5 가능)
- 설정 패널 "기본" 섹션에 `시야: 좁게/보통/넓게` = preference 0.95/0.78/0.62. localStorage 저장 (검색어: `loadLocalProfile` 패턴 재사용).

## 금지·주의
- **baseTargetZoom(조준 배율표)과 clamp 하한 0.6은 건드리지 말 것** — 렌더 컬링·미니맵·성능이 이 대역 기준으로 튜닝돼 있음. 0.6 밑으로 내리고 싶으면 먼저 30유닛 전투에서 FPS 확인.
- 저격 조준을 "기본 시야"로 만드는 안은 기각됨: 저격의 정보 우위가 사라져 병과 개성이 죽는다. 대신 1번(전체 기본 시야 확대)으로 해결.
- 온라인 동기화 무관 (카메라는 클라이언트 로컬) — 안전한 작업.

## 검증
1. `npm run check`.
2. PC 브라우저 → 설정 → "모바일 조작 UI" 켜기 → 시야가 즉시 넓어지는가, 핀치(터치 에뮬레이션)로 조절되는가.
3. 실기기 가로모드: 이동 중 전방 시야에 적이 화면 밖에서 갑자기 나타나는 빈도가 줄었는가 (주관 확인).
4. 조준 시 기존 줌아웃과 중첩돼 과도하게 멀어지지 않는가 (저격 조준 시 0.72×0.78=0.56 → clamp 0.6에 걸림 — 의도된 동작, 확인만).

## 코드 불일치 기록 (2026-07-05)

작업 중단. 설계도 전제와 현재 코드가 다르다.

- 설계도는 "모바일은 `cameraZoomPreference`를 바꿀 수단이 없어 기본 1에 고정"이라고 하지만, 현재 `src/systems/mobile-camera-gestures.js`가 이미 로드되어 `setMobileControls`, `onPlayerCameraWheel`, `updateCamera`, `setupMobileCameraGestures`를 패치한다.
- 현재 모바일 기본값은 0.7이다. 설계도 지시값 0.78과 다르다.
- 현재 모바일 휠/핀치 클램프는 [0.55, 1.3]이다. 설계도 지시값 [0.6, 1.2]와 다르다.
- 현재 모바일 `updateCamera` 패치는 조준 중 `cameraZoomPreference`를 임시로 0.7 또는 0.85 배로 더 낮춘다. 설계도는 기존 조준 배율표는 그대로 두고 preference만 조절하라고 되어 있어 의도가 다르다.

AGENTS.md 규칙에 따라 코드를 설계도에 맞추지 않고 여기 기록 후 중단한다. 다음 작업자는 먼저 이 설계도를 현재 코드 기준으로 갱신할지, 아니면 기존 `mobile-camera-gestures.js` 구현을 폐기/수정할지 결정해야 한다.

## 불일치 해소 판정 (2026-07-05, Fable)

**판정: 코드가 이긴다. 이 설계도의 수치 지시(0.78, [0.6, 1.2], preference만 조절)는 폐기한다.**

- 현재 `mobile-camera-gestures.js` 구현이 설계 의도를 이미 충족한다: 모바일 기본 0.7은 지시값 0.78보다 오히려 더 넓은 시야이고, 클램프 [0.55, 1.3]도 더 넓은 조절 범위이며, 조준 시 추가 축소(×0.7/0.85)는 "조준 시 줌아웃" 의도의 구현이다.
- 따라서 모바일 FOV는 **신규 코드 작업 없음.** 남은 것은 검증뿐이다: R1 게이트 G2의 "모바일(실기기): 시야 확보 상태로 이동·조준 가능" 칸에서 확인한다. 실기기 체감이 나쁠 때만 0.7/클램프 수치를 튜닝 후보로 재개봉한다.
- 이 문서는 이 판정으로 종결. 이후 모바일 카메라 작업은 새 문서로.
