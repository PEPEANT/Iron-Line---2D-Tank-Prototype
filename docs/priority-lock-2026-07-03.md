# 우선순위 고정 (2026-07-03)

이 문서는 프로젝트 오너가 확정한 작업 순서다. 모든 작업자(사람, Petos, Codex, Fable)는 새 작업을 시작하기 전에 이 문서를 따른다. 순서를 바꾸려면 이 문서를 먼저 수정한다.

## 확정 순서

1. **전투 루프 완성** — 전장 템포 마무리
   - D2: 제압이 축적되지 않는 근본 원인 추적 (`docs/battlefield-tempo-diagnosis-2026-07-03.md` 참조)
   - D3: 학살 후 정체 해소 (지휘관 우세 판단 → 재공세)
   - 완료 기준: `node tools/check-battlefield-tempo.cjs` 2~3회 평균이 진단 문서의 목표 대역 충족
2. **모바일 조작감 / 카메라** — 1번과 병렬 가능 (건드리는 파일이 다름: input/카메라/CSS)
3. **라이브 2P 육안 확인 + 플레이를 막는 버그** — 보간 버퍼(3359256)의 실기기 검증 포함
4. **코드 기반 타격감/판독성 폴리시** — 피격 플래시/넉백/이펙트 소품. 에셋 아님
5. **에셋 / 디자인 패스** — 루프 증명 후. AI 에셋은 VFX/초안 용도
6. **착수 금지 (1~4 완료 + 실제 플레이어 검증 전까지)**: 건물/차량 내부, 도시/오픈월드, 경제 시스템, 50v50, UGC/창작마당, 서버 권위 전면 재설계

## UGC / 스팀 창작마당에 대한 입장

방향은 옳다. 그러나 순서가 있다:

- 창작마당은 "에셋을 만들어주는 곳"이 아니라 "이미 플레이어가 있는 게임에 팬이 에셋을 얹는 곳"이다. 모드 공급은 플레이어 수요를 따라온다. 빈 창작마당은 죽은 게임 신호가 된다.
- UGC를 열려면 에셋 스키마(hull/turret/pivot/footprint 규격)를 동결해야 하는데, 이 규격은 만들어진 지 며칠 안 됐고 아직 바뀌어야 한다.
- 현재 진행 중인 asset-pack 구조(`assets/packs/` manifest + `asset-registry.js` + 테스트랩 스킨 워크벤치)가 **바로 창작마당의 내부 절반**이다. 이 계약을 "언젠가 외부인이 팩을 만든다"는 전제로 계속 다듬으면, 루프 증명 후 창작마당 전환은 재구축이 아니라 스위치 켜기가 된다.

즉 UGC는 폐기가 아니라 5번 뒤의 예약석이다.

## 운영 규칙

- 새 시스템 아이디어는 이 문서 하단 "대기 목록"에 적고 착수하지 않는다.
- 한 번에 하나를 고치고, 템포/스모크 도구로 재측정한 뒤 다음으로 간다.
- 커밋은 작게, public push는 오너 승인 전까지 보류.

## 대기 목록

- **지휘관 뷰 프로토타입 (우선순위 4.5 예약 — 에셋 패스보다 먼저)**: RTS형 전장 카메라 + 탭 명령 + 유닛 탭 시 빙의(기존 3인칭 조작 재사용). 재료는 전부 있음: 관전/옵저버 카메라, CommandBus, 전술맵, V2 AI. 1~2일 타임박스로 만들어 플레이 후 판정 — "위에서 지휘가 본편"으로 느껴지면 게임 정체성을 지휘관 뷰 중심으로 공식 전환하고 에셋 스케일 기준을 그에 맞춘다. 테마는 실제 우크라이나 전쟁 직접 차용 금지(스토어 심사/리뷰 리스크), 현대전 영감 가상 분쟁으로.
- 행군 구간(접촉까지 ~78초) 이벤트 채우기: 정찰 접촉, 포격 경고 등
- 전차가 보병 교전보다 먼저 킬을 내는 개전 구도 검토
- 총탄/피격 물리 피드백: 아군 보병도 탄도 판정에서 몸으로 탄을 막는 느낌을 검토한다. 단, 실제 아군 피해/팀킬 활성화는 별도 판단으로 분리한다. 우선순위는 총알이 통과하지 않는 판독성, 피격 시 짧은 넉백/튕김/몸 움찔, 엎드림 상태 피격 반응 같은 코드 기반 타격감이다.
- 테스트랩/스킨 연구실 작업대형 UI 재배치 (Petos 설계안 있음)
- 앉아쏴(crouch) 3단계 자세
