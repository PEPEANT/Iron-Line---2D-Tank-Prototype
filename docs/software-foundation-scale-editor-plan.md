# 소프트웨어 기반 / 대규모 전장 / 맵에디터 계획

2026-07-04 플레이 판단: 전차와 보병 수를 최대로 올리면 렉이 심해진다. 이 문제는 단순 최적화 티켓이 아니라, 수복을 스토리모드, 맵에디터, 대규모 현대전으로 확장하려면 지금부터 소프트웨어 기반을 제대로 잡아야 한다는 신호다.

## 결론

수복은 "기능을 계속 붙이는 프로토타입"에서 "성능 예산과 콘텐츠 제작 파이프라인이 있는 게임 소프트웨어"로 넘어가야 한다.

지금 당장 모든 것을 갈아엎지는 않는다. 대신 다음 원칙을 고정한다.

- 최대 병력/전차 수는 재미 옵션이 아니라 성능 게이트다.
- 맵에디터는 장식 툴이 아니라 스토리모드와 전장 확장의 기반 데이터 제작 도구다.
- AI는 분대 명령만 따르는 덩어리가 아니라, 각 유닛이 현재 장비와 상황에 맞는 행동 후보를 가져야 한다.
- "렉이 난다"는 말은 FPS 하나가 아니라 update, AI, pathfinding, tactical map, renderer, effects, UI, snapshot 중 어느 축인지 분해해야 한다.

## 현재 판단

### 1. 최대 설정 렉

현재 전투 설정은 전차/보병 수를 크게 늘릴 수 있다. 하지만 과거 스케일 문서의 정상 진행 기준은 8v8, 15v15, 25v25 같은 단계형 프로필이었다. 사용자가 임의로 최대치를 올리는 것은 25v25보다 더 무거운 조건이 될 수 있다.

따라서 "최대 설정에서도 부드러워야 한다"는 목표는 맞지만, 바로 그 수치를 기본 목표로 삼으면 안 된다.

먼저 해야 할 일:

- 현재 최대 설정을 공식 스케일 프로필로 이름 붙인다.
- `frameMs`, `aiMs`, `pathfindingAndMovementMs`, `tacticalMapMs`, `renderMs`, `effects count`, `projectile count`를 분리해서 측정한다.
- 최대 설정은 통과/실패를 명확히 기록한다. 실패하면 자동으로 낮은 스케일 프로필로 내려가는 구조를 둔다.

### 2. 맵에디터는 처음부터 중요하다

스토리모드가 "평범한 직장인이 갑자기 전쟁을 만나는" 형태로 확장된다면, 맵은 단순 배경이 아니라 사건을 배치하는 데이터가 된다.

맵에디터가 앞으로 다뤄야 할 것:

- 건물, 도로, 엄폐물, 장애물, 거점.
- 유닛/전차/차량의 시작 위치.
- 민간 구역, 직장/집/피난로 같은 스토리 노드.
- AI 이동 경로, 방어선, 매복 지점, 후송 지점.
- 향후 실내/건물 진입과 요새화의 기준점.

그래서 맵에디터는 "그림을 놓는 툴"이 아니라 `map schema`를 만드는 툴이어야 한다.

### 3. 침대전투는 아이템 부족 문제이기도 하다

AI가 누워 있기만 하는 것은 단순히 엎드림 계수가 강해서만은 아니다. 누운 뒤 할 수 있는 행동 후보가 부족하다.

필요한 행동 후보:

- 전차/험비를 향한 소화기 제압 사격 또는 견제 사격.
- RPG병 호출, 대전차포 설치, 박격포 요청 같은 대항 행동.
- 연막 투척 후 이동.
- 부상병 응급처치 또는 후송 요청.
- 같은 자리에서 오래 누워 있으면 산개 또는 엄폐 이동.

전차에 소총 피해를 크게 넣자는 뜻은 아니다. 피해는 낮아도 "쏘고 있다 / 위치를 찍고 있다 / 대전차병에게 넘긴다"는 행동이 있어야 플레이어 눈에 AI가 살아 있는 것처럼 보인다.

## 소프트웨어 발전 원칙

### 1. 성능 예산을 코드보다 먼저 둔다

각 스케일 프로필은 목표를 가진다.

| 프로필 | 목적 | 예산 |
| --- | --- | --- |
| R1 기본 | 첫 플레이 기준 | 안정 FPS, 전투 체감 우선 |
| R1 대형 | 사용자가 병력을 올린 상태 | 프레임 드랍 원인 분해 |
| R2 스토리 | 스토리맵 + 이벤트 + AI | 맵 데이터와 이벤트 비용 포함 |
| 이벤트 대규모 | 50v50류 후보 | 관전/스트레스 전용, 기본 모드 금지 |

최대 설정은 "지원한다고 말하기 전" 반드시 프로브가 있어야 한다.

### 2. 핫스팟 파일에 기능을 더 쌓지 않는다

이미 `main.js`, `renderer.js`, `hud.js`, `infantry-ai.js`, `map-editor.js`는 큰 파일이다. 새 기능은 아래처럼 분리한다.

- 성능 계측: `src/systems/performance-*` 또는 tools 프로브.
- AI 전술 후보: `src/ai/infantry-*`의 작은 행동 모듈.
- 맵 스키마/프리셋: `src/data/maps/*` 또는 문서화된 map schema.
- 맵에디터 팔레트/배치: `src/tools/map-editor-*`.
- 스토리 이벤트: 게임 루프 안에 직접 박지 않고 `scenario event` 데이터로 분리.

### 3. 맵에디터는 도감과 연결한다

순서:

1. 도감 v1: 에셋 크기, pivot, 진영 색, 파츠 조립 검수.
2. 맵 스키마: 맵 파일이 무엇을 저장하는지 확정.
3. 에디터 팔레트: 도감에서 검수된 유닛/건물/오브젝트를 선택해 배치.
4. 전투 로딩: 맵 스키마를 실제 전장으로 불러오기.
5. 스토리 노드: 직장, 집, 피난 지점, 전선 변화 같은 사건 배치.

이 순서를 지키면 "에셋 추가 → 도감 검수 → 맵에 배치 → 플레이 테스트" 루프가 생긴다.

### 4. AI는 분대 명령 + 개별 판단으로 간다

분대장은 방향과 의도를 준다.

- 전진
- 엄폐
- 재집결
- 산개
- 후퇴
- 대전차 대응
- 부상병 구조

개별 유닛은 자기 장비와 상태로 행동을 고른다.

- 소총수: 견제 사격, 이동, 엄폐, 부상병 지원.
- 기관총/지원화기: 엎드려 제압, 긴 사선 유지.
- RPG/공병: 장갑 위협 우선, 사격 각도 확보.
- 정찰병/저격수: 바로 돌격하지 않고 시야와 표적 지정.
- 향후 의무병: 전투불능 아군 소생.

이 구조가 있어야 누워 있는 AI가 "멈춘 AI"가 아니라 "지원화기로 눌러주고, 다른 병사가 움직이는 분업"으로 보인다.

## 최적화 접근

### 1단계: 계측 강화

최대 설정 플레이를 감으로 보지 않는다. 반드시 카운터를 남긴다.

- 총 유닛 수, 활성 AI 수, LOD 단계별 수.
- 탱크/험비/드론 수.
- 현재 탄환/이펙트/폭발/연기 수.
- 프레임별 `update`, `AI`, `pathfinding`, `tacticalMap`, `render`.
- 미니맵/전술지도 렌더 비용.

### 2단계: AI LOD를 실제 행동에 적용

이미 LOD 분류 문서와 도구가 있으므로 다음은 적용이다.

- 화면 밖 먼 유닛은 매 프레임 판단하지 않는다.
- 멀리 있는 분대는 분대 단위로만 이동하고, 근접하면 개별 AI를 켠다.
- 탄환/사선 계산은 가까운 교전 구역 중심으로 한다.
- 전술지도 구조 재계산은 이벤트 기반으로 늦춘다.

### 3단계: 공간 분할

대규모 전장에서는 모든 유닛이 모든 유닛을 매번 검사하면 안 된다.

- spatial grid / cell 기반 근처 검색.
- 총알, 폭발, 시야, 충돌, 엄폐 후보를 셀 기준으로 줄인다.
- 맵에디터도 같은 셀 구조를 사용해 배치 검증을 빠르게 한다.

### 4단계: 렌더링 비용 분리

- 멀리 있는 보병은 단순 점/실루엣으로 그린다.
- 체력바/말풍선/생각표시는 가까운 유닛 또는 선택 유닛만.
- 폭발/연기는 개수 제한과 풀링을 둔다.
- 미니맵/전술지도는 매 프레임 전체 재렌더하지 않는다.

### 5단계: 콘텐츠 게이트

스토리모드, 맵에디터, 에셋 증가가 들어오면 성능이 다시 나빠진다. 따라서 새 콘텐츠는 아래를 통과해야 한다.

- 에셋 도감 검수 통과.
- 맵 스키마 검증 통과.
- R1 기본 스케일 FPS 통과.
- R1 대형 스케일에서 병목 분류 가능.

## 스토리모드 확장 기준

스토리모드는 별도 게임을 하나 더 만드는 일이 아니다. 현재 전장 엔진이 아래 데이터를 읽을 수 있게 되면 자연스럽게 열린다.

- 시작 직업/장소: 회사, 집, 도로, 대피소.
- 첫 사건: 공습, 검문, 통신 두절, 전차 진입.
- 동료 AI: 이름, 상태, 역할, 기억.
- 목표: 살아남기, 합류, 대피, 구조, 거점 확보.
- 전장 변화: 도로 차단, 건물 파괴, 후송로 변경.

즉 스토리모드의 핵심은 대사문이 아니라 맵 데이터와 AI 상태 변화다. 그래서 맵에디터가 먼저다.

## 하지 말아야 할 것

- 렉이 난다고 전차/보병 수만 무작정 줄이지 않는다.
- 성능 계측 없이 수치만 튜닝하지 않는다.
- 맵에디터를 새 엔진으로 갈아엎지 않는다.
- 스토리모드를 텍스트 이벤트부터 만들지 않는다.
- 모든 AI 유닛에게 모든 행동을 한 번에 넣지 않는다.

## 다음 작업

1. `max-scale` 프로필을 만든다.
   - 현재 UI에서 가능한 최대 전차/보병 설정을 이름 있는 프로필로 저장한다.
   - 프로브로 병목을 분해한다.

2. 침대전투 계측을 만든다.
   - 폭발 뒤 `prone-only`, `spread`, `cover`, `fallback`, `anti-armor-response` 비율을 기록한다.

3. 맵 스키마 문서를 만든다.
   - 도감/맵에디터/스토리모드가 공유할 `{assetId, x, y, rot, team, tags}` 기준을 확정한다.

4. 도감 v1을 만든 뒤 에디터 팔레트를 붙인다.
   - 검수된 에셋만 맵에 배치할 수 있게 한다.

5. AI 행동 후보를 장비별로 늘린다.
   - 소총수는 견제/이동.
   - 지원화기는 제압.
   - RPG/공병은 장갑 위협 대응.
   - 의무병/후송은 전투불능 시스템 이후.
