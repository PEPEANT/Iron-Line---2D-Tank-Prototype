# 에셋 도감/검수실 설계도 — 구현 지시서

작성: 2026-07-04, Fable 5. Codex 제안 검토 결과 반영. 순서 합의: **도감 → (에셋 늘어난 뒤) 맵에디터 팔레트 연동**. 맵에디터 엔진화는 하지 않는다.

## Codex 제안에 대한 판정

동의:
- 도감이 맵에디터보다 먼저다. 기준 없는 배치 툴은 나중에 전부 꼬인다.
- 3D는 지금 만들지 않고 "표현 교체 가능성"만 유지한다.

반박 1 — **새 카탈로그 스키마에 게임플레이 값을 넣지 말 것.**
Codex 안의 `collisionFootprint`, `coverValue`는 이미 게임 데이터(scenery-catalog.js, 엔티티 설정)에 존재한다. 카탈로그 JSON에 복제하면 진실이 두 곳이 되고 반드시 어긋난다. 이 프로젝트는 이미 "에셋팩에 게임플레이 키 금지"(lockedGameplay, 체커가 강제)를 원칙으로 잡았다 — 도감도 같은 원칙: **도감 v1은 새 데이터가 아니라 기존 데이터 위의 뷰(view)다.** 표시용 충돌/엄폐 정보는 게임 데이터에서 읽어와 그리기만 한다.

반박 2 — **future3d 필드를 지금 넣지 말 것.**
게임 로직은 이미 id로 움직이고 표현은 렌더러가 담당(스프라이트 슬롯 + 벡터 폴백) — 2D→3D 교체점은 구조적으로 이미 존재한다. 빈 `modelPath: null` 필드는 지금 아무것도 보장하지 않으면서 스키마 관리 비용만 만든다. 3D 확장 가능성은 "표현/로직 분리 유지"라는 규율로 지키는 것이지 필드로 지키는 게 아니다.

## 구현: 테스트랩에 "도감" 탭 추가 (신규 화면 아님)

기반: `src/systems/test-lab-asset-preview.js` (이미 원본 vs 파츠 비교 캔버스, 이미지 캐시, bbox 크롭 보유), `test-lab-ui.js` (탭 구조).

### v1 범위 (이것만)
1. **그리드 목록**: 등록된 모든 시각 자원을 카드로 나열 —
   - 세력 6종 (`IronLine.playerFactions`: 로고 + cloth/vest/accent 색)
   - 전차 파츠 (asset pack image 슬롯: `vehicle.tank.*` — 현재 lab-ai-tank 팩)
   - 무기 일러스트 12종 (`assets/weapons/*.png`, INFANTRY_WEAPONS 순회)
   - 배경/오브젝트 (`IronLine.sceneryCatalog` — 벡터 렌더 항목은 미니 캔버스에 렌더 함수 호출로 그림)
2. **카드 공통 표시**: id, 카테고리, 출처(벡터/PNG/팩), 월드 크기 박스 오버레이(스프라이트가 게임 내 몇 유닛인지 — 전차 84×54 기준선과 겹쳐 그림), 이미지 미로드 시 "빈 슬롯" 표시.
3. **진영 전환 토글**: 카드 상단 blue/red 버튼 → 전차는 `vehicle.tank.hull.blue/.red` 슬롯 조회, 보병은 faction 색 팔레트 적용 렌더.
4. **검수 오버레이 토글 1개**: pivot 십자선 + 월드 크기 박스 + (게임 데이터에서 읽은) 충돌 반경 원. 조절 UI는 만들지 않는다 — 수치 조정은 manifest/데이터 파일 직접 수정 후 새로고침 (도감은 눈, 손은 파일).

### v2 (에셋 30개+ 되면)
- 파츠 조립 뷰 (hull+turret 합성 미리보기 — test-lab 비교 캔버스 로직 재사용)
- 파괴 상태(wreck) 나란히 보기

### v3: 맵에디터 팔레트 연동 (유저 확정 방향 — "심플 배치 맵엔진")
루프: **도감에서 검수 통과한 에셋 = 에디터에서 배치 가능한 에셋.** 같은 목록 함수를 두 화면이 공유한다.
1. 도감의 목록 빌더를 `IronLine.assetCatalogList()` 공용 함수로 분리 (테스트랩 탭과 에디터가 같이 호출).
2. `src/tools/map-editor.js`에 팔레트 사이드바 추가: 카테고리 필터(유닛/차량/건물/오브젝트) + 카드 클릭 선택 → 캔버스 클릭 배치 (드래그보다 터치 호환 좋음), R 회전, Del 삭제, 그리드 스냅.
3. 배치 결과는 **맵 스키마**(r1-release-gate.md 백로그의 맵 파이프라인 항목)에 기록 — `{assetId, x, y, rot, team}`. 스키마 문서가 선행 조건.
4. 에디터 "엔진" 재작성 금지: 기존 map-editor.js의 카메라/저장 로직 유지, 팔레트와 배치 핸들러만 추가.
순서 고정: **도감 v1(검수) → 맵 스키마 문서 → 에디터 팔레트(v3)**. 이 셋이 끝나면 "AI가 초안 깔고 사람이 에디터에서 유닛·건물을 바로 놓는" 원하는 형태가 완성.

### 금지
- 새 JSON 카탈로그 파일 생성 금지 (v1은 런타임 데이터 순회만으로 충분)
- 도감에서 게임 수치 편집 기능 금지
- 3D 프리뷰/필드 금지

## 검증
`npm run check` 통과 + 테스트랩 진입 → 도감 탭에서 세력 6/무기 12/전차 파츠가 보이고, 진영 토글과 크기 오버레이가 동작하면 완료. 이때 "에이브럼스/군인/건물 추가"는 파일 드롭 → 도감에서 크기 확인 → manifest 수치 조정 루프가 된다.
