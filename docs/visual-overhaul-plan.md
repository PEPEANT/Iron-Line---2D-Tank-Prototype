## 0. 우선순위와의 관계

- 이 계획 = [priority-lock-2026-07-03.md](priority-lock-2026-07-03.md) **4번(코드 기반 타격감/판독성 폴리시) + 5번(에셋/디자인 패스)을 하나의 트랙으로 묶은 것.**

- 병렬 진행 중인 렉 수정(코덱스, 폴링/localStorage)과 파일 겹침 없음: 이 트랙은 renderer 계열 + CSS만 만진다.
- "갈아엎기"의 정의: **엔진/시스템 재작성이 아니라, 같은 시스템 위에 통일된 시각 언어를 단계별로 입히는 것.** restart 반사 아님.

## 1. 근본 진단 — 왜 "전부 이상"해 보이는가

한 문장: **게임 화면의 기본 시각 언어가 "디버그 오버레이"다.** 기능이 만들어질 때마다 작업자(AI 에이전트)가 각자 색/알파/선굵기/점선을 임의로 골랐고, 통일 규칙이 없어서 화면 전체가 "엔지니어링 진단 뷰"처럼 보인다. 개별 증거:

1. **조준이 4가지 스타일**: `renderer.js drawPlayerInfantryAim(:972)`이 기관총/권총/RPG 모드만 처리하고 **소총(주무기)은 fall-through로 레티클이 아예 없음(:984)**. 권총은 점선+원+크로스, 기관총은 다른 색 크로스, RPG는 3중 원(최소사거리 링 + 레티클 + 스플래시 링)이 겹쳐 소음. → "주무기 조준이 없고, 보조무기는 이상하고, 중화기는 더 이상함"의 정체.
2. **지형이 모눈종이**: `drawTerrain(:550)` = 선형 그라디언트 1장 + 원형 패치 + **균일 그리드(alpha 0.14, 120px)**. 질감/노이즈/방향성 없음. 에셋 티의 최대 주범.
3. **상시 점선/링 과다**: 정찰드론 scanRange 원이 **비조종 시에도 항상 렌더**(`renderer-drone.js drawDroneRangeAndLink(:46)`, alpha 0.055~0.13) — 스크린샷의 거대한 파란 점선 호. 드론-소유자 링크선도 상시.
4. **폭발에 섬광·가산합성 없음**: [explosion-impact-plan.md](explosion-impact-plan.md) ②는 "섬광(가산합성) → 화구 → 연기 + 파편 선분"이었으나, 구현(`renderer-explosions.js:82`)은 `globalCompositeOperation = "source-over"` 고정에 **섬광 단계·파편 선분 미구현**. 화구가 밋밋한 이유.
5. **잔상(흔적) 부재**: `scorchMarks`는 전차 탄약 경로에서만 생성(`combat.js:1152, :1188` — `ammo.scorchRadius` 기반). **수류탄/RPG/자폭드론 폭발은 그을림이 안 남거나 약함.** debris 데칼(explosion-debris.js)이 모든 폭발 유형을 커버하는지 미검증. → "투척류/폭발류 잔상이 안 남는다"의 정체.
6. **자폭드론 기폭이 범용 폭발 재사용**: 전용 연출(기체 조각, 프로펠러 파편, 전기 스파크) 없음.
7. **텍스트 우선 UI**: 결과 화면 `작전 실패`(hud.js:916)가 맨 텍스트. 시스템 알림이 영어 혼용("Squad pressure critical; retreat recommended"). 무전기/HUD도 동일 문제(→ 초안 이미 있음: [design-drafts/radio-hud-redesign.html](design-drafts/radio-hud-redesign.html)).
8. **소품에 라이트 규칙 없음**: 보급상자 = 밋밋한 베이지 사각형 4개. 그림자/재질/디테일 부재.
9. **무기 비주얼 전체가 플레이스홀더**: `assets/weapons/*.png` 12종 전부 150~280바이트(빈 껍데기). 이 파일을 아이템창(infantry-slotbar-hud.js:15), 보급 UI(supply-crates.js:291), 로비(lobby-ui.js:737), 배치화면(deployment-ui.js:245), 테스트랩 **5곳이 공유** → 어느 화면이든 구버전으로 보임. 인게임 탑다운 무기(`renderer.js drawInfantryWeapon(:1453)`)도 둥근 사각형 2~3개라 12종이 같은 막대기로 보임. 보급 v2 체계([supply-loadout-blueprint.md](supply-loadout-blueprint.md): 주무기/보조/중화기/지원장비/투척류/설치류)는 시스템만 들어가고 비주얼이 안 따라감.

## 2. 디자인 언어 v1 (모든 단계가 따르는 헌법)

이 절이 이 문서의 핵심이다. 개별 수정보다 **규칙**이 재발을 막는다.

### 팔레트 토큰 (신규 색 임의 추가 금지 — 여기서 고르기)
```text
지형        #213922 / #263d26 / #1f3429 (기존 유지) + 흙 #3a3428 / 마른풀 #4a4a30
아군(청)    #679b9a 계열
적군(홍)    #c95d4a 계열
포커스/조작  #ffd166 (앰버) — "플레이어가 지금 조작 중인 것"에만
위험/경고    #ff6b5e — 피해/기폭/실패에만
섬광/열     #fff6c6 → #ff913a → #37322a (폭발 온도 그라데이션)
```

### 선(라인) 규칙
- **점선은 "플레이어가 지금 조작 중인 대상" 전용.** 상시 점선 금지. (드론 사거리 원, 상시 링크선 → 조종 중에만)
- 정보 링은 동시에 최대 1개. (RPG의 3중 원 → 스플래시 링 하나만, 최소사거리는 tooClose 상태색으로 대체)
- 월드 안 디버그성 도형(그리드 포함)은 기본 꺼짐이 목표.

### 레티클 공통 규격 (모든 무기 동일 골격)
```text
골격: 중앙 도트 + 4방향 갭 크로스 (기존 MG 스타일 기반)
무기별 차이는 "크기·확산·색"만:
  소총(신설)  중간 크기, 연사 시 확산 애니메이션
  권총        소형, 점선 궤적선 제거
  기관총      대형, 지속사격 시 열 확산
  RPG        대형 + 스플래시 링 1개
상태색: 사거리 내 = 앰버 / 사거리 밖 = 저알파 / 쿨다운·탄약 없음 = 레드
```

### 라이트/섀도 규칙 (모든 월드 오브젝트)
- 탑다운 뷰 기준 **남동쪽 소프트 섀도 1개 + 북서쪽 상단 하이라이트 1개.** 보급상자·전차·장식물·잔해 공통.

### 텍스트 다이어트
- 월드(캔버스) 안 텍스트 금지. HUD는 아이콘 우선(무전기 초안과 같은 철학). 시스템 알림은 전부 한글 + 아이콘 접두.

## 3. 단계별 작업 (각 1~2세션 · 순서 = 체감 대비 비용)

### P1. 지형·바닥 — ✅ 적용 완료 (2026-07-06)
`src/systems/renderer-terrain.js` 신설: 시드 고정 노이즈 타일(흙 얼룩+풀결 스트로크+알갱이, 256px 오프스크린 1회) 패턴 채움, 그리드 0.14→0.04 톤다운, 월드 외곽 비네트(그라디언트 캐시). 성능 프로브 allPass (renderMs 1.4~2.3).
- 그리드: alpha 0.14 → 0.04 이하 또는 교차점 틱(+)만 남기기. `terrainStyle.gridAlpha` 활용.
- **오프스크린 노이즈 캔버스 1회 생성** 후 `createPattern`으로 채움: 흙 얼룩·풀 뭉치 밀도 변화·미세 명암. 프레임당 비용 0.
- terrainPatches 다양화: 원형 그라디언트 일변도 → 방향성 스트로크(풀결), 불규칙 흙 자국 2~3종.
- 외곽 비네트(가장자리 어둡게)로 화면 중심 유도.
- 파일: `renderer.js drawTerrain` (+ 필요시 `renderer-terrain.js` 분리, 300줄 규칙).

### P2. 조준 통일 — ✅ 적용 완료 (2026-07-06)
`src/systems/renderer-player-reticle.js` 신설: 소총·기관단총·저격·LMG·기관총 레티클 신설(기존 부재), 전 무기 공통 골격(원+4갭 크로스+도트) + 무기별 크기/gunKick 확산, 상태색 통일(앰버/저알파/레드). RPG는 조준선+스플래시 링 1개로 축소(최소사거리 링 제거 → tooClose 색 표현). 구 MG/권총 전용 함수 경로 대체.
- **소총 레티클 신설** (현재 아예 없음 — 최우선).
- 4종 → 공통 규격(위 헌법)으로 재작성. `drawPlayerReticle(mode)` 하나로 통합.
- RPG: 3중 원 → 레티클 + 스플래시 링 1개. 최소사거리 위반은 링 대신 레티클 색·형태로 표현.
- 파일: `renderer.js :826~1128` 일대.

### P3. 폭발·잔상 (1~2세션) — "잔상이 안 남는다" 해소
- 섬광 단계 추가: 0~0.06s 흰 원, **`globalCompositeOperation = "lighter"`(가산)** — 원계획 ② 복원.
- 파편 선분 6~10개 방사형(0.2s, tracer 재사용) — 원계획 ② 복원.
- **모든 폭발 경로에서 scorch + debris 생성 보장**: 수류탄/RPG/자폭드론이 `ammo.scorchRadius` 없이도 그을림을 남기도록 폭발 생성부에서 일괄 처리. 연기 잔류 시간 연장(현행 대비 2~3배, 상한 FIFO 유지).
- 자폭드론 전용 기폭: 범용 폭발 + 기체 조각(회색 사각+프로펠러 선, 원계획 ④에 이미 정의됨) + 짧은 전기 스파크. 명중/벽/수명종료 모두 동일.
- 파일: `renderer-explosions.js`, `combat.js` 폭발 생성부, `explosion-debris.js`, `suicide-drone.js detonate(:503)`.

### P4. 드론 시각 정책 — ✅ 적용 완료 (2026-07-06)
`renderer-drone.js drawDroneRangeAndLink`: scanRange 원은 조종 중에만, 소유자 링크선은 신호 경고(weakSignal)일 때만 렌더. 화면의 거대 점선 호 제거됨.

### P5. 소품 리디자인 (1세션)
- 보급상자: 베이지 사각형 → 군용 크레이트(판자 결 2~3선, 금속 모서리, 스텐실 마킹, 남동 그림자). 오프스크린 캐시 1회 렌더 후 drawImage.
- 장식물(수풀/바위/잔해) 동일 라이트 규칙 적용. scenery-catalog 스타일 일괄 점검.
- 파일: `supply-crates.js` 렌더부, `renderer-scenery.js`, `scenery-catalog.js`.

### P5.5. 무기 비주얼 전면 교체 (1~2세션) — 아이템창·보급·인게임 전부
무기 12종: rifle / smg / lmg / machinegun / pistol / sniper / grenade / grenadeLauncher / rpg / repairKit / reconDrone / kamikazeDrone.

- **(a) 무기 아이콘 렌더러 신설** (`src/systems/weapon-icon-renderer.js`): 무기별 절차적 벡터 아이콘을 오프스크린 캔버스에 1회 렌더 → dataURL 캐시. 12종 각각 실루엣이 구분되게(총열 길이·탄창 위치·개머리판·스코프·탄두 등) 디자인 언어 팔레트로 그림.
  - **PNG 드롭인 규약 유지**: `assets/weapons/<id>.png`가 실제 아트(플레이스홀더보다 큰 파일)면 그걸 우선 사용, 아니면 절차적 아이콘 폴백. 기존 "파일 덮어쓰기 = 교체" 계약 그대로.
  - 적용 지점 5곳 일괄: 아이템창(infantry-slotbar-hud) · 보급 사물함(supply-crates) · 로비(lobby-ui) · 배치(deployment-ui) · 테스트랩(test-lab-asset-preview). 전부 같은 렌더러를 쓰므로 한 번 그리면 모든 화면이 동시에 신버전.
- **(b) 인게임 탑다운 무기 리디자인 — ✅ 적용 완료 (2026-07-06)**. 목업(weapon-visuals-mockup.html v2: 게임 원본 캐릭터 + 신규 무기) 오너 승인 후 `src/systems/renderer-infantry-weapons.js` 신설로 반영. `drawInfantryWeapon` 프로토타입 교체(renderer-explosions.js 패턴), 무기 12종 개별 아트, 오프스크린 스프라이트 캐시(무기당 full/carry 2변형, 프레임당 drawImage 1회), 자세·반동 변환 로직은 원본 그대로 유지. index.html에 스크립트 1줄 추가. `npm run check` 전체 통과 확인.
- **(c) 보급 v2 카테고리 정합**: 보급 사물함 UI의 카테고리(주무기/보조/중화기/지원장비/투척류/설치류)와 아이템 목록이 supply-loadout-blueprint v2와 일치하는지 점검, 카테고리별 탭 아이콘 부여.

### P5.7. 차량 계기판(대시보드) 디테일 패스 — ✅ 적용 완료 (2026-07-06)

- 목표: 무전기·드론 조종기 초안(v3)과 **같은 기기 재질 언어**로 통일 — 올리브드랍/다크 트림/앰버 포인트.

  - 속도계·차체 다이얼: 눈금(major/minor 틱) + 숫자 각인 + 바늘 축 캡 + 베젤 링 + 유리 광택 + 레드존
  - 주포 클러스터: 탄종 표시를 기계식 플립 카운터 느낌으로, 장전 게이지는 계기 안 호(arc) 게이지로
  - MG 잔탄: 7세그먼트 LCD 스타일 (앰버 발광)
  - 연막: 실물 경고등 램프(렌즈 돔 + 점등/소등) + Q 키캡 각인
  - 패널 자체: 나사 4개, 브러시드 금속 상판, 계기 사이 리벳/분할선, 하단 러버 트림
  - 험비: 같은 언어로 속도계 + HMG + 차체만 (스펙 유지)
- 원칙 유지: **실존 상태만 계기화** (연료/기어 등 가짜 계기 금지 — 원본 스펙 그대로). 데이터 소스 계약(`tank.speed/ammo/reload/hp/smokeCooldown`) 변경 없음, 렌더만 교체.
- 착수 조건: P5.5(무기 비주얼)와 같은 절차 — HTML 목업으로 오너 확인 후 실코드 반영. 코덱스 렉 작업과 무관하게 목업은 먼저 만들 수 있음.

- 시스템 알림 전부 한글화 + 아이콘 접두 (`B-SQD-5: Squad pressure critical` → `⚠ B-5분대 압박 한계 · 후퇴 권고`).
- 무전기·드론 상태 HUD: [design-drafts/radio-hud-redesign.html](design-drafts/radio-hud-redesign.html) **v2** 초안을 실코드 반영 (command-radio.js + hud.js + CSS).
  - **오너 결정 (2026-07-06)**: 무전기 패널·채널·명령 그리드(이동/공격/방어/집결/돌격) **전부 폐기** — "실제로 한 번도 안 썼다" = 불편하다는 증거. 대체: **원버튼 무전기** — 무전기 모양 버튼 하나, 누르면 주변 아군이 플레이어 위치로 집결(기존 rally 명령 경로 재사용), 송신 연출 1.2초 + 쿨다운 링 4초.
  - 주의: CommandBus/명령 시스템 코드는 AI 지휘관·관전이 쓰므로 유지. 걷어내는 건 **플레이어용 UI만**.
  - 드론 위젯: **펼친 노트북(야전 조종 단말) 형태**, WASD 키캡 제거, 드론 전용(포탄 장전 상태는 전차 계기판 소관이라 제외). 상태 = 색 + 한 단어 (대기/조종 중/표적/자폭 준비/복귀 중).

## 4. 성능 규칙 (렉 수정 트랙과 충돌 금지)

- **프레임당 새 그라디언트/캔버스/배열 생성 금지.** 질감·소품은 오프스크린 캔버스에 1회 굽고 재사용.

## 5. 검증

- 단계마다: 관리자 스폰으로 폭발/드론/보급상자 재현 → 스크린샷 전후 비교.
- 최종 체크리스트: "화면에 디버그 오버레이로 보이는 요소가 남아 있는가?" (상시 점선/그리드/맨 텍스트/영어 알림 = 실패).
- 템포 프로브(deaths/min 6~12) 유지 확인 — 시각 변경이 판독성을 해쳤는지 감지.

## 6. 분담 제안

- **코덱스**: 렉 수정 마무리 후 P3(폭발·잔상) — 폭발 코드 컨텍스트 이미 보유.

## 7. 재발 방지

- 새 시각 요소를 추가하는 모든 작업자는 **이 문서 2절(디자인 언어)을 먼저 읽고 팔레트/선/라이트 규칙 안에서만 그린다.** 규칙을 벗어나야 하면 이 문서를 먼저 수정.
- "일단 점선/링으로 표시" 습관 금지 — 정보 표시가 필요하면 레티클 규격·LED·아이콘 중에서 선택.
## 8. 2026-07-07 플레이테스트 아트 후속 기록

결론: 오늘 보병 기본 스킨을 실제 플레이에 넣어본 결과, R1 알파의 다음 시각 병목은 "프레임 수 부족"과 "세력/무기별 식별성 부족"이다. 확장 기능보다 아래 항목을 먼저 닫는 편이 맞다.

### 확인된 문제

1. 엎드린 상태에서 죽을 때 전용 사망 모션이 충분히 드러나지 않는다.
   - 현재는 엎드림/기어가기/사격 프레임은 들어갔지만, 사망 전환 연출은 아직 빈약하다.
   - 우선순위: 높음. 누운 상태에서 피격 -> 엎드린 사망 프레임으로 자연스럽게 이어지는지 확인해야 한다.

2. 사망 관련 모션 수가 적어서 같은 시체 자세가 반복되어 보인다.
   - 현재 사망 프레임은 `dead-01`, `dead-02`, `dead-prone` 수준이라 전투가 길어지면 금방 고정 패턴처럼 보인다.
   - 다음 작업: 방향/자세/피격 상태별 사망 프레임을 더 확보한다.

3. 적 스킨을 빠르게 넣어야 한다.
   - 아군만 새 스킨이면 전장 식별성은 좋아져도 세계관 밀도는 부족하다.
   - 북한군/중국군/테러조 등 스토리 세력별 탑뷰 색, 장비, 헬멧 실루엣을 분리해야 한다.

4. 총기마다 다른 형태의 총 스킨이 필요하다.
   - 이건 무기 아이콘만 바꾸는 문제가 아니다.
   - 보병 스킨 작업과 함께, 캐릭터가 실제로 들고 있는 총 실루엣도 rifle/smg/lmg/machinegun/pistol/sniper/rpg 등으로 분리해야 한다.
   - 결론: 보병 스킨 파이프라인을 정리할 때 총 스킨까지 같이 묶어서 처리한다.

5. 탱크 스킨도 바꿔야 한다.
   - 보병 아트가 올라가면 기존 전차/험비가 상대적으로 낡아 보인다.
   - 세력별 차량 색, 궤도, 포탑, 장갑 디테일을 단계적으로 교체한다.

6. 캐릭터 크기가 바뀌었으므로 맵 스케일도 재검토해야 한다.
   - 새 보병 스프라이트가 커지면서 기존 샌드박스/맵의 도로 폭, 엄폐물 간격, 건물 크기가 상대적으로 작거나 넓게 느껴질 수 있다.
   - 다음 맵 작업에서는 보병 크기, 차량 크기, 도로 폭, 골목 폭, 엄폐물 밀도를 함께 맞춘다.

## 9. 유혈/피격 묘사 구조 계획 (2026-07-09)

결론: 유혈은 순간적으로 크게 튀는 이펙트보다 `피격 이벤트 -> 몸에서 떨어지는 피방울 -> 바닥 번짐/흐름 -> 시체 주변 웅덩이 -> 절단 파츠`로 이어지는 전용 시각 시스템으로 분리한다. 이번 단계에서는 방향/크기/그림자 보정만 하고, 혈액 시스템은 아래 계약으로 따로 착수한다.

### 목적

- 총탄 피격 시 몸 아래로 작은 피방울이 뚝뚝 떨어지고, 바닥에서 짧게 번진다.
- 연속 피격/치명상은 피방울 간격이 짧아지고 바닥 얼룩이 서로 이어져 흐르는 느낌을 만든다.
- 차량 충돌/폭발은 짧은 피 튐을 허용하지만, 기본 표현은 바닥에 번지는 혈액과 웅덩이를 중심으로 둔다.
- 이후 절단 팔, 떨어진 무기, 피 묻은 파츠를 같은 이벤트 구조에 붙일 수 있어야 한다.

### 시스템 흐름

1. `BloodEvent` 생성: 보병 `takeDamage`, 폭발 피해, 차량 충돌, 사망 판정에서 위치/방향/강도/피해 종류를 기록한다.
2. `BloodDrips`: 0.35~1.4초짜리 낙하/흐름 입자. 총탄은 몸 주변 아래쪽으로 떨어지고, 이동 중이면 진행 방향으로 짧게 끌린다.
3. `BloodDecals`: 바닥에 남는 작은 방울/번짐/이어진 얼룩. 수명은 길지만 개수 상한과 풀링을 둔다.
4. `CorpseBlood`: 시체 주변 웅덩이와 느린 피 흐름. 사망 자세와 별도 레이어로 그린다.
5. `GoreParts` 확장: 폭발/차량 충돌에서 절단 파츠 PNG를 떨구는 단계. 파츠 그림이 준비된 뒤 연결한다.

### 데이터 계약

- 이벤트 필드: `{ x, y, angle, amount, damageType, lethal, sourceSpeed, victimRadius }`
- 드립 필드: `{ x, y, vx, vy, r, life, maxLife, alpha, gravity, trail, seed }`
- 데칼 필드: `{ x, y, rx, ry, angle, alpha, kind, wetness, flowDir, createdAt }`
- 유닛 상태 필드 후보: `bloodLevel`, `bleedRate`, `wounds[]`, `lastBloodEventAt`

### 성능/설정 규칙

- 프레임마다 새 캔버스 생성 금지. 피 얼룩 모양은 몇 개의 오프스크린 스탬프로 굽는다.
- 드립 상한 120, 데칼 상한 220부터 시작하고 FIFO로 제거한다.
- 설정에 `유혈 묘사 낮음/보통/높음/끄기`를 둔다.
- 절단 묘사는 `높음`에서만 켜고, 기본값은 피방울/바닥 번짐/시체 웅덩이까지만 둔다.

### 착수 순서

1. `src/systems/blood-effects.js` 신설: 이벤트 큐, 드립 풀, 데칼 풀.
2. `renderer-blood.js` 또는 renderer 확장 모듈 신설: 지형 위, 보병/차량 아래 레이어에 그리기.
3. 보병 `takeDamage`와 사망 판정에 작은 드립 이벤트만 연결.
4. 차량 충돌/폭발에 강한 이벤트 연결.
5. 절단 파츠 PNG가 준비되면 `GoreParts`를 별도 단계로 연결.
